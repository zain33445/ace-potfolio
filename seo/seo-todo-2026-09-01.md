## 1. Switch every URL to a trailing slash

> **DONE — shipped and verified 2026-09-02** (commit `d578bfa`, worker `3c9a7cbb`). Confirmed in the Ahrefs crawl of 2026-09-02 17:24Z: zero redirect chains, all 43 site redirects resolve to a 200 in one hop. Remaining follow-up: resubmit the sitemap in Search Console.

**Effort:** half a day · **Priority: do this before any other item** · **Must ship as one deploy**

The WordPress site served every URL with a trailing slash, so that is the form Google indexed and has ranking history for. The Next.js rebuild has no `trailingSlash` setting, which means it defaults to `false` — every one of those historical URLs now 308-redirects:

```
/warehouses-development/  -> 308 -> /warehouses-development
/about-us/                -> 308 -> /about-us
```

August GSC confirms the signals still sit on the slashed form. The pages carrying real impressions were all slashed:

| URL | Impressions | Position |
|---|---|---|
| `/warehouses-development/` | 450 | 68.8 |
| `/hotels-development/` | 196 | 69.1 |
| `/quantity-surveyor-services/` | 171 | 38.1 |
| `/project-management/` | 155 | 69.0 |
| `/educational-buildings/` | 130 | 79.4 |

The non-slash variants that also appeared (`/services`, `/about-us`, `/blog`, `/projects`) carried brand queries and near-zero clicks. Restoring trailing slashes makes the historically-indexed URLs live 200s again, and lands every external backlink on a 200 instead of a redirect.

### The change

Set `trailingSlash: true` in `next.config`. That flips the framework default, but it does **not** update anything hardcoded — and every hardcoded destination currently points at the non-slash form. Left alone, each one becomes a two-hop chain (`old URL -> 301 -> non-slash -> 308 -> slash`), which is worse than the situation today.

**All of the following must change in the same deploy:**

| What | Count | File |
|---|---|---|
| `trailingSlash: true` | 1 | `next.config` |
| Hardcoded canonical URLs | **14** | `src/app/**/page.tsx` |
| Sitemap entries | **15** | `src/app/sitemap.ts` |
| Redirect destinations | **12** | `next.config` |
| Middleware redirect targets | **16** | `src/middleware.ts` |
| Internal `<Link href>` values | **10** | `src/**/*.tsx` |

Six consolidated blog posts already 301 into `/warehouses-development` (Cluster A in `src/middleware.ts`) — those destinations in particular must gain the slash, or that consolidation degrades into chains.

### Verify before deploying

```bash
curl -sSI --max-redirs 0 https://theaceservices.com/about-us | head -3
```

Expected afterwards: `/about-us` returns **308 → /about-us/**, and `/about-us/` returns **200**. Exactly the reverse of today. Then check that no URL takes two hops, and resubmit the sitemap in Search Console.

### Honest caveat

This is a second URL migration in under a month, and each one costs Google time to reprocess. It is worth doing because the ranking history is on the slashed URLs and the current state strands it — but it is the last URL-form change that should ever happen here. Pick trailing slashes and never revisit it.
